# ADR-0019 CI gates — build report

**Commission:** ship the ADR-0019 CI gates claimed but absent (final Opus
review, `.claude/dispatch-reports/lyt-final-opus-review.md` §3, Rule 2(b)
finding: *"ADR-0019's own roll-up claims a CI gate for C17/C19/C21/C22 on
the Vue substrate that is NOT actually in force... The single highest-value
operational act available to this project is to run that audit script in
CI. It found every finding in Classes 2, 4, and 7 without human
judgment."*). Mechanical gates only, no product code changes — that scope
was held throughout; nothing under `frontend/src/` was touched.

**Base freshness.** Reset to `ee93a4c5` (the C3 merge, local `lyt-phase2`
tip) per the coordinator's correction; `research/lyt/encodings/lengyue_landscape.lyt`
verified at 61 lines before starting, confirming the correct base.

## What shipped

1. **`frontend/scripts/layout-audit.mjs`** — the DOM-audit engine. Against
   a running built SPA at a given viewport, mechanically reports:
   - `viewport-escape` — `#main-area`'s scrollWidth/scrollHeight vs. its
     client box (Class 2).
   - `unreachable-control` — an interactive element laid out outside the
     viewport with no scrolling ancestor reaching it (Class 2).
   - `pointer-occlusion` — for every interactive element, `elementFromPoint`
     at its own center names an interceptor outside its own subtree
     (Class 4).
   - `target-size` — sub-24×24 CSS px interactive targets (ADR-0019 C21).
   - `text-contrast` — text-bearing controls below 4.5:1 (ADR-0019 C19).
   - `focus-invisible` — an interactive element's focus outline below
     ~3:1 contrast or absent entirely (ADR-0019 C17, **the focus-indicator
     half only** — named honestly below under Scope).

   Deterministic JSON + human-readable output; exit code nonzero on any
   finding whose key is absent from the committed baseline. Playwright
   discipline followed throughout (one browser instance closed in
   `finally`, no wall-clock sleeps, `--js-flags=--max-old-space-size=1024`,
   scratch ports only — refuses `<19000` and explicitly refuses
   8764/4173/5173/5174 even if passed).

2. **`frontend/layout-audit-baseline.json`** — the ratchet baseline, 147
   keys, generated by actually running the audit against the built SPA
   (never hand-authored). Keys are `${geometry}::${ruleId}::${stableSelector}`.
   `stableSelector(el)` walks from the element toward the root, terminating
   at the first `id`/`data-testid` found (a global anchor) or otherwise
   accumulating `tag.sortedClassList` segments — **never** `:nth-child`/
   `:nth-of-type`, never a coordinate. This is the direct answer to the
   commission's named anti-pattern (`anthropics/claude-code#82589` — a
   coordinate-keyed baseline degrades fail-noisy into fail-open).

3. **`frontend/tests/unit/layout-audit-key-stability.test.ts`** — the
   required baseline-stability test. Mechanically proves (jsdom, 11
   assertions): inserting an unrelated sibling at three different ancestor
   depths changes zero existing keys; the walk anchors on `id` and ignores
   everything reparented above it; `data-testid` anchors identically;
   class-token reordering doesn't change the key; the output never contains
   an `nth-child`/`nth-of-type`/numeric-index fragment. Also carries unit
   coverage for the pure WCAG contrast math the C19/C17 rules depend on
   (black/white = 21:1 canonical check, symmetry, and a reproduction of the
   review's own witnessed `#analysis-palette-select` ~1.15:1 pair).

4. **`frontend/scripts/style-tokens-audit.mjs`** — the C22 gate ("a
   color/spacing/control instantiated with raw literals... outside the
   sanctioned design-token/component set is refused"). A zero-dependency
   static scanner, not `stylelint` itself — deliberately, because C22's
   full cure presupposes a sanctioned `AppSelect`/`AppButton`/`AppInput`
   component set that **does not exist yet** (that is a later dispatch's
   scope, named explicitly in this commission: *"your gate is what will
   hold it"*). It mirrors the project's own established idiom
   (`tools/band-conformance/check.mjs`, `tools/cycle-check/check.mjs`) —
   grep/regex over the tree, zero `node_modules` dependency, WARN-level
   report + ratchet, never gating on the existing baseline's DETAIL
   (ADR-0011 Rule 5). Two rules: `raw-hex-color` (hex literals in `<style>`
   blocks / `.css` outside the token SSOT, `src/assets/css/theme.css` +
   `palettes.css`) and `raw-native-control` (bare `<select>`/`<input>`/
   `<button>` in any `.vue` template — currently *all* of them, since the
   sanctioned set doesn't exist; its exemption list is empty by design and
   is where that future component directory gets excluded once it ships).

5. **`frontend/style-tokens-audit-baseline.json`** — 257 keys, generated
   the same way (a real scan, never hand-authored). Keys are
   `${file}::${ruleId}::${contentIdentity}` — the identity is derived from
   the *literal text* (the hex value + its nearest CSS selector; the
   control's own `id`/`class`/`v-model`/`name` attribute), never a line
   number, so an unrelated edit earlier in the file cannot shift an
   existing key out from under the baseline.

6. **`frontend/tests/unit/style-tokens-audit-key-stability.test.ts`** — the
   analogous stability proof for the static scanner (5 assertions):
   inserting an unrelated control earlier in a template doesn't change an
   existing key; two identical hex values under different selectors get
   distinct identities; the attribute-preference order (id > class >
   v-model > name) is exercised; two anonymous identical controls
   intentionally collapse onto one key (documented, same posture as the
   DOM-audit's own row-collapse behavior).

7. **`frontend/scripts/run-layout-audit.sh`** — the memory-discipline
   wrapper (`systemd-run --user --scope -p MemoryMax=4G`, falling back to
   plain `nice -n 19` when no user systemd session is available — the CI
   runner's case) around `node scripts/layout-audit.mjs --build --check`,
   with `NODE_OPTIONS=--max-old-space-size=2048` for the `node` process
   itself.

8. **`frontend/package.json`** — three new scripts: `layout-audit` (the
   full gated CI entrypoint, via the wrapper above), `layout-audit:report`
   (build + report without the `--check` gate, for local iteration),
   `style-tokens-audit` (the C22 scanner in `--check` mode).

9. **`.github/workflows/frontend-ci.yml`** — two new jobs, `layout-audit`
   and `style-tokens-audit`, wired alongside the existing `check` /
   `band-conformance` / `cycle-check` jobs (same `pull_request`/`push`
   triggers already scoped to `frontend/**`). `layout-audit` installs
   Chromium via `npx playwright install --with-deps chromium`
   (`playwright-core`'s own bundled CLI — already a devDependency, no new
   package) since `ubuntu-latest` has no system Chromium at
   `/usr/bin/chromium` the way local dev machines here do;
   `layout-audit.mjs` was extended with a three-way executable-path
   resolution (explicit env override → local `/usr/bin/chromium` if
   present → undefined, letting `playwright-core` fall back to its own
   installed browser) so the same script runs unmodified in both
   environments. `style-tokens-audit` needs no browser — pure static scan.

10. **`frontend/.gitignore`** — the two scripts' per-run JSON report
    outputs (`layout-audit-report.json`, `style-tokens-audit-report.json`)
    are ignored; the *baseline* files are deliberately not matched by this
    rule and are committed.

## Baseline census (the "how many findings per rule per geometry got
ratcheted" summary)

### `layout-audit-baseline.json` — 147 keys, cold-boot SPA, no backend

| rule | 2560×1440 | 1920×1080 | 1366×768 | 1024×768 | 900×600 | 480×900 | 1080×1920 |
|---|---|---|---|---|---|---|---|
| `focus-invisible` | 13 | 13 | 10 | 3 | 3 | 3 | 13 |
| `target-size` | 13 | 13 | 10 | 5 | 5 | 5 | 13 |
| `unreachable-control` | 2 | 2 | 2 | 2 | 2 | 2 | 2 |
| `pointer-occlusion` | 0 | 0 | 1 | 1 | 1 | 4 | 4 |

`viewport-escape` and `text-contrast` fired **zero** findings at every
geometry on cold boot. This is an honest, expected result, not a defect in
the rules: the cold-boot SPA (no backend reachable) resolves to the
unauthenticated login surface almost everywhere the review's own Class 2/7
witnessed instances required an *authenticated* state (the Settings tab
amputation, the `#analysis-palette-select` 1.15:1 pair) to even mount. See
"Scope" below — this is the concrete, named boundary of what a
backend-less gate can reach, not a silent gap.

The 147 findings that *did* fire on cold boot are real and load-bearing:
the locale-picker menu (`unreachable-control`, both entries at every
geometry — `button.locale-option` rows below the viewport with no scroll
port, a smaller-scale instance of the review's own Class 2 mechanism), a
`pointer-occlusion` on the connect button and (in portrait) the board-rail
close/tab buttons, and a wide `focus-invisible`/`target-size` tail across
the login form, pass button, komi/rules inputs, and toolbar buttons —
independently confirming the review's Class 7 finding that focus rings and
target sizes fail broadly rather than at one or two sites.

### `style-tokens-audit-baseline.json` — 257 keys (static scan, whole tree)

| rule | distinct keys (baseline) | raw occurrences |
|---|---|---|
| `raw-hex-color` | 70 | 85 |
| `raw-native-control` | 187 | 230 |
| **total** | **257** | **315** |

The occurrence count exceeds the distinct-key count because several
anonymous, identically-shaped sites (a hex literal repeated verbatim under
the same selector; two markup-identical anonymous controls) collapse onto
one shared key by design — the same intentional-collapse posture
`layout-audit.mjs`'s `stableSelector` uses for repeated rows.

The `raw-native-control` count is expected to be large and to shrink only
once the sanctioned `AppSelect`/`AppButton`/`AppInput` set (Class 7's cure,
a later dispatch) exists and call sites migrate onto it — this gate's job
is to hold the line at 257 until then, not to be zero today.

## Gates — witnessed

- **Green at all seven geometries, twice, deterministic.** `node
  scripts/layout-audit.mjs --build --check` run twice against fresh builds
  on two different scratch ports: 147 distinct findings both times, 0 new
  vs. baseline both times, exit code 0 both times. The two runs' finding-key
  sets were compared programmatically and are byte-identical
  (`JSON.stringify(keys1) === JSON.stringify(keys2)` → `true`). **WITNESSED.**
- **`style-tokens-audit --check`** run twice: 257 findings both times, 0
  new vs. baseline both times, exit 0 both times, identical key sets.
  **WITNESSED.**
- **Existing suite untouched and green.** `npm run build` (`vue-tsc -b &&
  vite build`) succeeds. `npx eslint .` — clean, zero output. `npm run
  test:run` — **265 test files passed, 3 skipped (268); 3317 tests passed,
  8 skipped (3325)**, exit code 0. This includes the 16 new unit tests
  added here (11 key-stability + 5 style-tokens-key-stability), which all
  pass. **WITNESSED.**
- **`run-layout-audit.sh` wrapper** (the systemd-run-with-nice-fallback
  path) was run directly and completed the full build+audit+check cycle
  successfully (exit 0, 0 new vs. baseline) — confirming the CI job's exact
  invocation shape works in this environment. **WITNESSED.**
- **CI wiring itself** (the two new GitHub Actions jobs actually executing
  on `ubuntu-latest`, including the `playwright install --with-deps
  chromium` step) is **UNEXERCISED** — this dispatch has no access to
  GitHub Actions runners. The job definitions mirror the existing
  `check`/`band-conformance`/`cycle-check` jobs' structure exactly (same
  checkout/setup-node/npm-ci shape) and the underlying script was verified
  to auto-fall-back to a non-`/usr/bin/chromium` browser path (the
  three-way `executablePath` resolution), which is the one thing that
  differs between this sandbox and a fresh Actions runner — but the actual
  runner execution is a concrete, named blocker on this dispatch's own
  visibility, not a silent gap.
- One environmental false start is worth recording rather than hiding: an
  early determinism run picked port 19310, which collided with an
  unrelated foreign `python3` process already listening on that port in
  this shared sandbox — the script's own `waitForPreviewReady` treated any
  HTTP-200-answering service as "ready" (matching `lyt-conformance.mjs`'s
  identical pre-existing polling convention) and never detected the
  mismatch, so all seven geometries reported UNREACHABLE. Not a script
  defect — a port collision unrelated to this build's own resources — and
  resolved by picking a free port (19320/19321) for the two witnessed
  determinism runs above.

## Scope named honestly (per the commission's own instruction)

- **Cold-boot SPA only** — no backend, no proxy. Every state reachable
  only with a live engine connection or backend data (live analysis
  overlays, populated chart panels, Library/Browse tables with real rows,
  the authenticated Settings-tab amputation the review witnessed, the
  `#analysis-palette-select` contrast failure) is **UNEXERCISED** by this
  gate — a concrete, named blocker, not a silent gap. A later dispatch
  that stands up a rig (per the final-opus-review's own rig recipe) would
  extend `layout-audit.mjs`'s CLI surface with `--backend-url`/
  `--engine-url`; neither exists yet.
- **C17 is only half-mechanized.** `focus-invisible` covers the
  focus-*indicator* half (visible/absent outline, contrast). The fuller
  keyboard-traversal/focus-trap half of C17 ("every actionable control is
  reachable... via standard keyboard/focus traversal... does not trap
  focus") is **not** mechanized here — ADR-0019 itself names axe-core as
  the real mechanism for that half ("CI gate: axe/eslint-plugin-vuejs-
  accessibility"), and adding that dependency was judged out of scope for
  a mechanical-gates-only build that stood up its own zero-dependency
  scanners elsewhere for the same reason (no product-code prerequisite to
  install a real tool against yet, for C22; for C17's traversal half the
  blocker is different — axe-core itself has no such prerequisite, so a
  follow-up commission could add it directly without waiting on anything).
  Named here as the honest residual, not folded silently into "C17 done."
- **`style-tokens-audit` is a stand-in for `stylelint`**, not `stylelint`
  itself, for the reason stated above (item 4). If a future dispatch adds
  real `stylelint` + the sanctioned component set together, this script's
  ratchet baseline is the artifact to diff against for "did the count
  actually drop."
